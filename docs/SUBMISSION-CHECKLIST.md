# Razorpay Buildathon submission checklist

## Before submission

- [ ] Push the complete repository to a **public GitHub repository**.
- [ ] Add this README as the landing page.
- [ ] Verify `mvn test`.
- [ ] Verify backend starts on a clean machine.
- [ ] Verify `npm install && npm run build`.
- [ ] Verify the dashboard can run the batch.
- [ ] Verify at least one action executes.
- [ ] Verify one STOP case cannot execute.
- [ ] Record a 5-minute unlisted pitch video.
- [ ] In the video, show recovered ₹ before discussing code.
- [ ] Explain what broke during development and how you fixed it.
- [ ] Do not use real payment credentials or real customer data.

## What to emphasize

1. Measured recovered money.
2. Bounded autonomy.
3. Stopping rules.
4. Policy guardrails.
5. Audit trail.
6. Root-cause diagnosis.
7. Expected net recovery optimization.

## What not to emphasize

- number of lines of code
- number of LLM calls
- "we used AI everywhere"
- a chatbot UI
- generic CRUD
